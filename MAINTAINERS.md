## What Maintainers Do

- **Review & merge PRs** — within one week for most; 48h for security-adjacent
- **Triage issues** — label, prioritize, assign (bug / feature / docs / good
  first issue)
- **Guard the brand** — canonical links, stats, and imagery live in
  `packages/core` / `packages/assets`; changes need owner sign-off
- **Keep CI green** — broken `main` gets priority over features
- **Run releases** — follow the [DEPLOYMENT.md](DEPLOYMENT.md) checklist
- **Enforce the Code of Conduct** — reports to
  Bigmoney@demontimeexotics.com answered within 48h

| App code / packages | 1 |

| CI / release workflows | Owner sign-off |
| SECURITY-relevant | Owner sign-off, coordinated disclosure |
| Version bumps / releases | Owner executes |

## Becoming a Maintainer

There's no formal ladder — it's earned in public:

1. Consistent, quality contributions over time (code + reviews + discussions)
2. Demonstrated care for the project's conventions and brand integrity
3. Trust on sensitive areas (releases, CI)
4. Existing maintainers nominate; owner confirms

Maintainers can step down anytime — just say the word, no drama
(even though we cover drama for a living 😈).
