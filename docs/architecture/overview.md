# Architecture Overview

The Demon Time Exotics monorepo is one repository producing five shipping surfaces — the GitHub Pages landing site, the Tauri desktop app, the Electron desktop app, the Expo mobile app, and the shared packages that feed all of them. This document explains how the pieces relate; deeper dives live in the sibling records (`decisions.md`, `monorepo.md`, `apps.md`, `packages.md`, `build-pipeline.md`, `security.md`).

## The shape

At the top level the repo splits into `apps/`, `packages/`, `tooling/`, `docs/`, `prompts/`, `wiki/`, and `discussion/`, plus the `.github/` automation tree. pnpm workspaces (declared in `pnpm-workspace.yaml` over the globs `apps/*`, `packages/*`, `packages/config/*`, and `tooling/*`) link every workspace package locally through the `workspace:*` protocol, so a change to `@dte/shared` is visible to every app on the next dev-server reload without any publish step. Turborepo (turbo.json) sits on top to schedule `build`, `dev`, `lint`, `typecheck`, `test`, and `clean` across the graph with caching keyed by inputs and dependency outputs.

The four apps in `apps/` are deliberately heterogeneous. The landing (`@dte/landing`) is a framework-free vanilla TypeScript site built with Vite, shipped to GitHub Pages under the `/demon-time-exotics/` base path. The Tauri app (`@dte/tauri`) wraps an identical-flavored web frontend in a Rust core under `src-tauri/`, with commands exposed through `generate_handler!` and capabilities declared in `capabilities/default.json`. The Electron app (`@dte/electron`) uses the classic three-process split — main, preload with `contextBridge.exposeInMainWorld("dte", …)`, and renderer — with IPC handlers guarded by the shared URL allowlist. The mobile app (`@dte/mobile`) is an Expo Router project whose five tabs (watch, roster, hub, alerts, more) render straight from the shared data layer.

## The data spine

`@dte/shared` (packages/shared) is the single source of truth, per ADR-0005. Every channel fact the surfaces display — the `CHANNEL` identity, `CHANNEL_STATS` (21,200 subscribers, 406 videos, 3,025,509 total views), `YOUTUBE_IDS`, the full `LINKS` registry, `PLATFORMS`, `TOP_VIDEOS`, the eleven-figure `ROSTER`, the six `PILLARS`, and the twelve `AFFILIATES` products — is typed there once. The helpers module adds the pure utilities every surface leans on: `formatCompact` (which renders 21200 as "21.2K" and 3025509 as "3M", the exact strings the hero counters animate toward), `isAllowedUrl` and `ALLOWED_URL_PREFIXES` (the allowlist that the Electron IPC handler and the mobile `Linking` wrapper both consult before opening anything external), plus formatting and date helpers.

`@dte/core` (packages/core) builds services on top of that data: `links.ts`, `stats.ts`, `figures.ts`, `pillars.ts`, and `content.ts` expose grouped, filtered, and derived views; `api/` is an offline-first `ApiClient` that falls back to the `CHANNEL_STATS` snapshot when no real endpoint is configured; `auth/` models the membership flow as a redirect; `stores/` implements a tiny pub/sub `Store<T>` used for stats, alerts preferences, and the capped watch-history cache. `@dte/ui` (packages/ui) completes the spine with framework-free DOM factories — `button`, `badge`, `statBlock`, `card`, `iconBullet` primitives and composed `statsRow`, `hubGrid`, `rosterChips`, `pillarGrid`, `topContentList`, `supportPanel`, `heroCtas`, `fireTicker` components — plus the theme token registry that maps `--dte-*` CSS variables onto the brand palette.

## The shared configuration

The four packages under `packages/config/` keep every workspace aligned. `@dte/config-eslint` ships the ESLint 9 flat config (with dist/target/.expo/.turbo ignores and the typescript-eslint recommended rules); `@dte/config-typescript` provides the `base.json`/`web.json`/`node.json`/`react-native.json` preset chain; `@dte/config-tailwind` exports the `dteColors`/`dteFonts`/`dteShadows` tokens and the animation keyframes (`flicker-in`, `reveal-up`, `ember-drift`) as a Tailwind preset; `@dte/config-vite` exposes the three Vite factories — `webPreset` (base path + port), `tauriPreset` (port 1420 strictPort, `TAURI_ENV_` envPrefix), and `electronPreset` (renderer root + port 5174). `@dte/assets` distributes the generated brand imagery (logo ladder from 16px to 512px, favicon.ico, social preview, hero background) and the font license notes.

## The delivery pipeline

GitHub Actions carries the repo from commit to shipped artifacts. `build.yml` runs the four-surface build matrix; `ci.yml` gates every PR on lint, typecheck, and the web builds; `deploy-landing.yml` publishes the landing dist to GitHub Pages on main; `release-tauri.yml` runs the four-target matrix (macOS, Linux AppImage/deb, Windows NSIS/MSI) through tauri-action; `release-electron.yml` builds NSIS/dmg/AppImage/deb installers with electron-builder; `release-mobile.yml` drives EAS builds for Android and iOS; `codeql.yml` scans for security issues. The `release.js` tooling script orchestrates the local side: it verifies a clean tree, runs the quality gates, bumps every workspace manifest in lockstep, moves the CHANGELOG "Unreleased" section under the new version, and commits + tags — pushing the tag is what arms the release workflows.
