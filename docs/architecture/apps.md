# The Four App Surfaces

What each app in `apps/` is, how it is structured, and what makes it distinct. All four share the data spine (`@dte/shared`), the brand tokens (`--fire` #ff5e1a, `--inferno` #ff2e00, `--purple` #8b2fd6, `--gold` #f5a623 on near-black `--ink` #050505), the animated stat counters (21,200 subscribers / 406 videos / 3,025,509 views), and the reveal-on-scroll + `prefers-reduced-motion` discipline. The differences are in the shell.

## apps/landing — the GitHub Pages site

The flagship surface: a framework-free vanilla TypeScript site built with Vite 5 and shipped to GitHub Pages under the `/demon-time-exotics/` base path (a project site, hence the base). `index.html` carries the full page — navbar, hero with the eyebrow/title/subtitle/CTA block and the stats card whose `data-count` attributes drive the counters, six top-content cards linking to YouTube searches, six pillar cards, the eleven-figure roster grid, the six-card platform hub, the support panel (Subscribe / Membership / Merch / Ko-fi), and the footer. `src/script.ts` powers the motion: the ember particle canvas (70 particles in fire hues, paused on tab-hidden), the IntersectionObserver reveal, the ease-out-cubic counters that render through `formatCompact`, the mobile nav toggle, and the scroll guard. Styles live in `src/styles/styles.css`; the hero background is processed through Vite (`src/assets/hero-bg.png`) so the base path is rewritten correctly. `App.tsx` and `main.tsx` exist as inert React-upgrade-path scaffolds per ADR-0007. Public assets include the favicon ladder (16→512), `CNAME` placeholder, and `.nojekyll` for Pages.

## apps/tauri — the Rust desktop shell

The Tauri 2 app wraps a web frontend in a Rust core. `src-tauri/Cargo.toml` names the crate `dte-desktop`; `src/lib.rs` builds the `Builder` with the opener and shell plugins and `generate_handler!` exposing four commands — `get_app_info`, `get_channel_stats`, `open_external`, and `spawn_cmd::check_stream_status` — with `AppMeta` state managed through `app.manage` in setup. `tauri.conf.json` pins the identifier `com.demontimeexotics.desktop`, devUrl on port 1420 (strictPort, so a port clash fails loudly rather than silently rebinding), `frontendDist: "../dist"`, a CSP, and bundle targets across Windows/macOS/Linux. `capabilities/default.json` scopes the permissions to `core:default` plus the opener URL permission and the shell spawn/execute grants. The frontend (`index.html`, `src/main.ts`, `src/lib/tauri.ts`, `src/styles/styles.css`) is the same DOM pattern as the landing, with a statusbar reporting the Rust side's health through `invoke("get_app_info")`, and `openUrl` routed through the plugin with the allowlist check.

## apps/electron — the compatibility desktop shell

The Electron 33 app uses the strict three-process model. `src/main/index.ts` takes the single-instance lock, builds the sandboxed `BrowserWindow` (through the `buildMainWindow` factory in `src/main/windows/`), and loads either `ELECTRON_RENDERER_URL` in dev or the built `dist/renderer/index.html` in production. `src/main/ipc/index.ts` registers `dte:app-info`, `dte:channel-stats`, and `dte:open-external` — the last guarded by the shared `ALLOWED_URL_PREFIXES` so only vetted domains ever reach `shell.openExternal`. `src/preload/index.ts` is the only bridge: `contextBridge.exposeInMainWorld("dte", api)` with `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true`. The renderer mirrors the Tauri frontend's structure and reads `window.dte`. `scripts/dev.mjs` orchestrates dev (Vite on 5174, then spawn Electron with the env var). `electron-builder.yml` targets NSIS/dmg/AppImage/deb with GitHub publishing.

## apps/mobile — the Expo app

The Expo SDK 51 / React Native app routes through Expo Router. `app/_layout.tsx` mounts the Stack under a `ThemeProvider` with the DTE theme (fire as primary); `app/index.tsx` redirects into the tab group. `app/(tabs)/_layout.tsx` defines the five tabs — watch ▶ / roster 😈 / hub 🌐 / alerts 🔔 / more ⋮ — each a thin screen over the shared data: `watch.tsx` renders the `TOP_VIDEOS` cards, `roster.tsx` the `ROSTER` chips with the purple third-chip variant, `hub.tsx` the `PLATFORMS` grid opening through `Linking.openURL` behind `isAllowedUrl`, `alerts.tsx` the `Switch` toggles for the five alert preferences (breaking, uploads, live, members, merch), and `more.tsx` the support card plus the `AFFILIATES` gear grid and about footer. `src/store/index.ts` carries the pure `createStore` reference implementation for the `AlertsPrefs` and watch-cache state. `eas.json` defines the three build profiles; `app.json` carries the `demontimeexotics` scheme and the iOS/Android bundle ids.
